# Защита текущей PHP-версии

Проверено локально 17.09.2026. Это базовое усиление приложения, не гарантия отсутствия всех уязвимостей и не внешний пентест хостинга.

## Реальная поверхность обработки

Сайт не имеет административной панели, базы пользователей, загрузки файлов или серверной отправки писем. Контактные формы формируют `mailto:` в браузере. Имя, телефон и текст обращения серверу не отправляются. Веб-приложение принимает только GET и HEAD. POST/PUT/PATCH/DELETE/TRACE отвергаются с 405; JSON-ошибка не повторяет отправленные данные. Поэтому в текущем приложении нет изменяющего состояние обработчика формы, для которого имел бы смысл CSRF-токен. Фиктивная «CSRF-защита mailto» не добавлялась.

Исправлена утечка при отключённом JavaScript: раньше форма без method/action отправляла поля через GET на текущую страницу. Теперь задан безопасный POST fallback, кнопка отключена до загрузки обработчика, есть noscript со ссылкой записи. Даже принудительная отправка формы не принимает персональные данные и не помещает их в URL.

`assets/form-guard.js` проверяет имя, полный российский телефон, email, длину текста и обязательное подтверждение. Получатель и тема письма фиксированы, значения полностью кодируются отдельно от параметров mailto. Скрытое поле и 30-секундный интервал мешают простым автоматическим и повторным действиям в интерфейсе; это **клиентские меры**, не серверная защита почты от спама. Данные не записываются в localStorage/sessionStorage.

## Серверные меры

- Общая CSP: только локальные скрипты, запрет inline-обработчиков, сторонних соединений, объектов и подмены base; iframe разрешены для используемых карт Яндекса. Inline-стили оставлены для существующей вёрстки и анимаций. CSP дополняет экранирование, не заменяет его.
- `frame-ancestors 'none'`, X-Frame-Options DENY, nosniff, Referrer-Policy и Permissions-Policy. Ошибки PHP и версия PHP не выводятся посетителю.
- HSTS включается приложением только при подтверждённом HTTPS от сервера. Заголовки forwarded не считаются доверенными.
- Проверка Host по явно настроенному `DZ_SITE_URL`; canonical не строится из пользовательских заголовков. Нормализуются стандартные порты 80/443. Loopback-алиасы допускаются только для локального происхождения.
- Публичные ресурсы разрешены по точному списку. Исходный архив, app/content/templates/docs/tests/tmp/vendor, скрытые файлы и старые PDF недоступны через HTTP. Путь не становится произвольным include.
- `/search-api` и `/search` принимают строку до 200 Unicode-символов. Массивы, некорректный UTF-8 и управляющие символы отвергаются. API не принимает cross-site fetch. Обе точки имеют общий лимит 30 запросов / 10 секунд и 120 / минуту для адреса соединения; превышение — 429 с Retry-After.
- Счётчики находятся в отдельном каталоге системного temp, с блокировкой файла и пределом количества записей. Хранятся HMAC адреса, число запросов и окончание окна. Поисковые строки, телефоны и тексты писем в этот файл не попадают. Истёкшие записи очищаются при следующих обращениях; отказ хранилища закрывает поиск ответом 503.
- Локальный router сам отдаёт разрешённые ресурсы, чтобы PHP static fallback не терял защитные заголовки. Поддерживаются корректные MIME, ETag/304, HEAD и кеширование; PDF помечены noindex.

## Проверки

- tests/security-http.mjs: 36 проверок заголовков, методов, закрытых файлов, Host, массивов/UTF-8, длины запроса и безопасного fallback формы.
- Настоящий TRACE проверен `curl.exe -X TRACE` — 405. Отдельный POST с X-HTTP-Method-Override тоже отклонён; эти проверки не смешиваются.
- tests/security-burst.mjs: 35 быстрых запросов попеременно к обоим поисковым адресам. Получены 200 и 429 с Retry-After; 5xx отсутствовали. После окончания короткого окна поиск работает снова.
- tests/rate-limit.php: ограничение, Retry-After, истечение окна, независимость клиентов и закрытый отказ повреждённого хранилища.
- tests/form-guard-unit.cjs: ограничения и попытки внедрения адресатов/заголовков в mailto.
- Браузер: без JavaScript кнопка отключена, method=post; заполнение ловушки блокирует подготовку; валидная форма создаёт кодированное письмо, повторный клик ограничен. Реальная отправка письма в тесте не выполнялась.
- В браузере проверены работа поиска с CSP и понятное сообщение при 429. Ошибок CSP и JS в этих сценариях нет. HTTP 429 в UI-тесте намеренно эмулировался, перехват снят после проверки.

## На реальном хостинге

1. Задать настоящий `DZ_SITE_URL`, включить HTTPS и редирект альтернативных хостов. Не использовать PHP development server как публичный production-сервер.
2. Проверить права файлов, приватность temp, обновления PHP/ОС, резервное копирование и восстановление. Не выкладывать исходный архив в отдельный открытый каталог.
3. Apache: конфигурация `.htaccess` подготовлена, но Apache в этой среде не запускался. Проверить поддержку mod_rewrite/mod_headers, правила AllowOverride; выставить `TraceEnable Off` на уровне сервера. На Nginx нужны эквивалентные правила — `.htaccess` он не читает.
4. Если есть reverse proxy/CDN, согласовать доверенные прокси и настоящий адрес клиента. Без этого лимит применяется к адресу прокси; слепо доверять X-Forwarded-For нельзя. Ограничение больших атак обеспечивается также веб-сервером/провайдером.
5. При добавлении SMTP/CRM/WordPress повторно проверить угрозы. Новый POST-обработчик требует серверной валидации, CSRF-защиты, лимитов, безопасного почтового транспорта, журналирования без лишних данных и обновлённых документов по персональным данным. Текущие меры клиента сами по себе его не защитят.
